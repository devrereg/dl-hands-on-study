# BatchNorm과 Gradient 안정성 실습

`batchnorm_and_gradient_stability.ipynb` 파일에 대한 소개입니다.

## 실습 목적

가상의 이진 분류 데이터를 이용해 **미니배치(minibatch) 크기의 영향**과 **BatchNorm(배치 정규화)의 효과**를 실험적으로 확인합니다. 특히 BatchNorm이 그래디언트를 얼마나 안정화시키는지, 그리고 그 효과가 배치 크기에 따라 어떻게 달라지는지를 다룹니다.

## 진행 흐름

1. **데이터 준비**
   `make_classification`으로 1000개 샘플, 20개 특성의 이진 분류 데이터를 생성하고, `train_test_split`으로 훈련/테스트(80/20) 분할 후 `StandardScaler`로 표준화

2. **배치 크기의 영향 실험**
   배치 크기 `[8, 32, 128, 512]`로 동일한 단순 모델(`SimpleNet`)을 각각 학습시켜, 배치 크기에 따라 학습 손실 곡선이 어떻게 달라지는지 비교

3. **BatchNorm 유무 비교**
   - `NetWithoutBN`: 일반 4층 MLP
   - `NetWithBN`: 각 Linear 층 뒤에 `nn.BatchNorm1d`를 추가한 동일 구조 MLP
   - 두 모델을 같은 조건(batch_size=32)으로 학습시켜 손실 곡선 비교(선형/로그 스케일)

4. **그래디언트 안정성 비교 (핵심 실험)**
   - `register_hook`으로 각 가중치 파라미터의 그래디언트를 실시간 기록
   - 하나의 배치(32개)에 대해 forward/backward를 1회 수행 후, 층별 그래디언트 크기를 시각화
   - **결과**: BatchNorm 없이는 층마다 그래디언트 크기 편차가 크지만, BatchNorm을 적용하면 여러 층에 걸쳐 그래디언트 크기가 비교적 고르게 유지됨 → 더 안정적인 학습 가능

5. **배치 크기별 BatchNorm 효과 비교**
   배치 크기 `[8, 16, 32, 64]` 각각에 대해 BatchNorm 유무 모델을 학습시켜 손실을 비교
   - **결과**: 배치 크기가 작을 때는 BatchNorm이 오히려 불리하고(배치 통계 추정이 불안정), 배치 크기가 커질수록 BatchNorm의 이점이 커짐

## 핵심 시사점

- BatchNorm은 배치 안의 평균/분산을 이용해 정규화하므로, **배치 크기가 충분히 커야 안정적인 통계를 얻어 제 성능을 발휘**함 (실무에서도 보통 32 이상 권장)
- 배치 크기가 매우 작은 상황(메모리 제약, 온라인 학습 등)에서는 BatchNorm보다 LayerNorm, GroupNorm 등 배치 크기에 덜 민감한 정규화 기법이 더 적합할 수 있음
- "BatchNorm은 항상 좋다"가 아니라 **"배치 크기라는 전제 조건이 맞아야 좋다"**는 것을 실험으로 보여주는 것이 이 노트북의 결론
