# 편향-분산 관찰 & 데이터 분할/누수 방지 실습

`bias_variance_data_split_leakage_prevention.ipynb` 파일에 대한 소개입니다.

## 실습 목적

모델의 **표현력(capacity)**이 커질수록 훈련 성능과 일반화(검증/테스트) 성능이 어떻게 달라지는지, 즉 **편향(bias)-분산(variance) 트레이드오프**를 직접 실험으로 확인합니다. 동시에 **train/val/test 데이터 분할**을 올바르게 수행해 데이터 누수(leakage)를 방지하는 방법도 함께 다룹니다.

## 진행 흐름

1. **데이터 생성**
   사인 함수에 잡음(noise)을 추가한 회귀 데이터셋 생성 (`y = sin(x) + noise`), 총 600개 샘플

2. **데이터 분할**
   `train_test_split`을 두 번 사용해 전체 데이터를 **train(60%) / val(20%) / test(20%)** 세 그룹으로 분리
   → 테스트 데이터는 학습·튜닝 과정에서 절대 사용하지 않아 누수를 방지

3. **모델 두 개 정의**
   - `small` (hidden=8): 저용량 모델 → 편향 큼, 분산 작음
   - `big` (hidden=128): 고용량 모델 → 편향 작음, 분산 큼

4. **학습 함수 작성**
   Adam optimizer + MSE 손실로 두 모델을 각각 학습시키며, 매 epoch마다 train loss와 val loss를 기록

5. **손실 곡선 비교**
   `small`과 `big` 모델의 train/val loss를 함께 그래프로 시각화 → 모델 용량에 따른 과소적합(underfitting) vs 과대적합(overfitting) 경향 관찰

6. **최종 평가**
   학습에 전혀 사용되지 않은 **test set**으로 두 모델의 최종 MSE를 비교해 일반화 성능을 확인

## 핵심 포인트

- 모델 용량이 클수록(뉴런 수 증가) 훈련 손실은 낮아지지만, 검증/테스트 손실은 오히려 나빠질 수 있음(overfitting)
- 반대로 용량이 너무 작으면 훈련 손실 자체가 높게 유지됨(underfitting)
- **test set은 최종 평가에만 사용**하고 학습·검증 과정에서는 절대 참조하지 않는 것이 데이터 누수 방지의 핵심
